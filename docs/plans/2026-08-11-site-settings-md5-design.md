# SafeFileHub MD5 与站点外观配置设计

## 背景

SafeFileHub 需要支持两项可运行时管理的能力：

1. 管理员通过 Web/API 开启全局 MD5 异步计算；开启后仅对之后完成上传的文件计算，所有拥有该文件 `read` 权限的用户可见摘要。
2. 管理员通过 Web/API 配置网站名称、登录页 Logo、导航页 Logo、favicon、全局基准配色和备案号。

## 已确认决策

- MD5 全局开关默认关闭，配置存储在数据库，不增加命令行参数。
- 开关开启后，新上传完成的文件进入异步计算队列；已有文件不自动回算。
- MD5 不新增 `checksum_read` 权限；文件列表/详情沿用现有 `read` 权限过滤。
- MD5 计算状态持久化为 `disabled`、`pending`、`computing`、`ready`、`failed`；服务重启将 `computing` 恢复为 `pending`。
- MD5 不改变下载权限，也不替代已有 SHA-256。
- 站点设置采用数据库单例，提供管理员 API 和管理员 Web 设置页。
- Logo/favicon 仅支持本地上传，不支持外部 URL；资源存储在受控 data 子目录，使用 opaque 文件名和数据库映射。
- 禁止 SVG，避免脚本注入和外链资源风险；图片类型、大小、像素、扩展名和内容均需校验。
- 备案号默认关闭；关闭时前端不渲染备案号。

## 默认值

- 网站名称：`SafeFileHub`
- 基准配色：`#2563EB`
- 备案号开关：关闭
- 备案号文本：空
- MD5 开关：关闭
- Logo/favicon：使用内置默认资源，未上传自定义资源时不暴露 data 路径。

## 数据与生命周期

新增站点设置单例和站点资源元数据。上传完成时在同一数据库事务内读取 MD5 开关，并为新文件写入对应状态。计算任务必须具备唯一领取语义，避免多个 worker 重复计算。对象读取使用流式 `crypto/md5`，不将整个文件载入内存。

文件删除与 MD5 任务必须幂等：删除前使文件对读端不可见，任务发现对象/文件已不存在时完成清理，不产生悬挂任务。启动恢复处理未完成任务，并设置有界重试，不能创建无限后台重试。

## API

公开：

- `GET /api/site-settings`：返回网站名称、颜色、备案号显示信息、公开资源 URL 和 MD5 展示所需公开状态；不返回内部路径。
- `GET /assets/site/{assetID}`：返回已验证的公开资源。
- `GET /favicon.ico`：返回当前 favicon 或默认资源。

管理员：

- `GET /api/admin/site-settings`
- `PUT /api/admin/site-settings`
- `POST /api/admin/site-settings/assets/{kind}`，`kind` 为 `login_logo`、`nav_logo`、`favicon`

所有写入操作复用现有管理员认证、审计和应用日志机制。上传资源采用请求大小上限、内容 sniff、尺寸限制和原子替换。

## 前端

扩展现有原生 JS/TS 单页：加载公开站点配置，登录区展示网站名称和登录 Logo，登录后导航区展示导航 Logo 和颜色主题，文件列表/详情在拥有 `read` 权限且 MD5 已就绪时显示值，计算中/失败显示明确状态。管理员设置页修改站点文本、颜色、备案号开关、MD5 开关并上传三类资源。用户输入使用安全 DOM API，不把未验证内容写入 `innerHTML`。

## 安全边界

- 只有管理员能修改站点设置或上传资源。
- 公开接口不泄露 SQLite 路径、对象 key、未授权文件信息或内部错误。
- 资源路径不可由用户控制；资源名由服务端生成。
- 备案号文本按文本节点渲染。
- MD5 仅在已有文件 `read` 授权检查之后返回。
- 日志不记录文件内容、密码、Cookie、Authorization、token 或敏感 query。

## 兼容性

新 migration 必须支持全新数据库和现有数据库升级；默认值保证旧部署行为不变：不启用 MD5，默认站点品牌仍为 SafeFileHub，备案号不显示。旧文件不产生 MD5 任务。
