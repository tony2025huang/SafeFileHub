# SafeFileHub transfer baseline — 2026-08-11

## Scope

This is a local harness baseline, not a network or storage performance claim.
No isolated `iperf3` peer was provided, so no `iperf3` command was run and no
network bandwidth figures are recorded.

## Measured guard results

Command:

```bash
GOTOOLCHAIN=local /usr/local/go/bin/go test ./bench -run 'Test(RunBounded|Healthz)' -count=1 -v
```

Result on the task runner:

- `TestRunBoundedDoesNotCreatePendingGoroutines`: pass.
  `Run(..., count=128, concurrency=2)` held peak active work at 2 and stayed
  within the guard's 12-goroutine allowance above its pre-run baseline.
- `TestHealthzResponsiveDuringSixteenConcurrentUploads`: pass.
  With 16 upload handlers intentionally blocked, `/healthz` returned `200`
  within the 250 ms test budget.

The test is a responsiveness guard. It does not provide a statistically useful
p99, throughput, CPU, RSS, disk wait, FD count, RTT, HTTP version, TLS, or
SSD/NAS comparison.

## Harness design

`bench.Run` uses exactly `min(count, concurrency)` workers and an unbuffered
job channel. It has no goroutine per waiting transfer and no unbounded pending
queue. `BenchmarkRun` exercises 1, 2, 4, and 8 workers against a 1 MiB
in-memory copy to `io.Discard`, so it measures local scheduling/copy overhead
only.

## Required next measurements

Record raw output under `bench/results/` for each intended deployment:

1. 1/2/4/8 transfer concurrency and 1/20/80 ms RTT.
2. HTTP/1.1 versus HTTP/2, with and without TLS.
3. SSD versus NAS storage, single stream versus bounded range/chunk parallelism.
4. Throughput, CPU, RSS, disk wait, FDs, error rate, and health p99.
5. `iperf3 -c <isolated-peer> -P 1` and `-P 4`, only when the isolated peer is
   named and authorized.

Do not tune chunk size, per-file parallelism, worker limits, socket buffers, or
application token buckets until those measurements exist. Do not change host
sysctls automatically.

## Local scheduler microbenchmark

Command:

```bash
GOTOOLCHAIN=local /usr/local/go/bin/go test ./bench -bench . -benchmem -count=1
```

Measured on the task runner (`linux/amd64`, `QEMU Virtual CPU version 2.5+`):

| Workers | ns/op | Reported MiB/s | allocs/op |
| ---: | ---: | ---: | ---: |
| 1 | 3,196 | 328,039.73 | 11 |
| 2 | 4,890 | 214,423.67 | 13 |
| 4 | 7,771 | 134,937.68 | 17 |
| 8 | 14,184 | 73,926.47 | 25 |

These figures are the harness's in-memory `io.Copy` microbenchmark, not file
or network transfer throughput; they must not be used to select production
concurrency.
